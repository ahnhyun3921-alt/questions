# 나답 질문 평가·제작 모델

매달 통계로 다시 학습하는 하나의 모델이에요. 기존 질문을 **평가**하고, 새 질문을 **만들고 고르는** 데 함께 써요.
- 코드: `analysis/qmodel.py`(모델), `analysis/build_insights.py`(학습·검증·출력), 페이지의 `modelPred`·`qstat`·`predict`
- 결과 파일: `board/data/insights.json`의 `model`

## 0. 평가 체계 한눈에 (2026-10 개편)

질문 하나를 다섯 층으로 평가해요. 아래 층의 출력이 위 층의 입력이에요(`build_insights.evaluate`, 결과는 `insights.json`의 `evals`).

| 층 | 무엇을 | 방법 | 쓰이는 곳 |
|---|---|---|---|
| ① 측정 | 결론 = 답변 + 교체 | 미응답 제외 — 결론 비율의 문항 간 표준편차 0.093이 이항 잡음 0.091과 같아서, 질문이 좌우하지 않아요 | 모든 층 |
| ② 설계 예측 μ | 문구 특성만으로 본 기대 답변율 | 릿지 베타-이항 회귀(2절) | 생성기·진단기·카드 편집 예측, 처방 |
| ③ 실적 추정 θ | 실제 답변율 | 사후 Beta(a + φμ, n − a + φ(1 − μ)), 80% 범위 | 등급 |
| ④ 등급·진단 | A 우수 / B 양호 / C 개선 권장 / D 수정 필요 / N 판정 보류 | 아래 규칙 | 카드 칩, 목록 필터 |
| ⑤ 처방·우선순위 | 무엇을 바꾸면 몇 %p 오르나, 무엇부터 | 반사실 μ 재계산 · 기대 이득 × 상대 노출 | '고쳐야 할 것' 탭 순서 |

### 등급 규칙 (결론 5회 이상)
| 등급 | 조건 |
|---|---|
| D 수정 필요 | P(θ < 평균 − 10%p) ≥ 0.8 |
| A 우수 | P(θ > 평균 + 10%p) ≥ 0.8 |
| C 개선 권장 | P(θ < 평균 − 5%p) ≥ 0.7, 또는 μ < 평균 − 5%p이면서 처방이 있음 |
| B 양호 | 나머지 |
| N 판정 보류 | 결론 5회 미만 — 설계 예측만 보여 줘요 |

2026-10-01 분포: A 5 · B 123 · C 19 · D 12 · N 1000.
- 활성 질문의 대부분은 아직 결론이 5회 미만(N)이에요.
- 등급은 표본이 쌓이는 만큼 자동으로 늘어나요.

### 진단
θ(실적)와 μ(설계 예측)를 비교해요.

| 진단 | 조건 | 할 일 |
|---|---|---|
| 설계 문제 | μ < 평균 − 5%p이고 처방이 있음 | 처방대로 특성을 바꿔요 |
| 소재·표현 문제 | P(θ < μ − 8%p) ≥ 0.6 | 형식은 괜찮아요. 소재나 말투를 바꿔요 |
| 숨은 강자 | P(θ > μ + 8%p) ≥ 0.6 | 새 질문의 본보기로 써요 |
| 예측대로 | 나머지 | — |
| 수정안 대기 | 개선본에서 문구를 바꾼 질문 | 통계와 태그는 지금 DB 문구 기준이에요. 바뀐 문구는 자동 태그로 μ만 따로 내요 |

- 지금 표본(문항당 결론 중앙값 2~3회)에서는 사후 추정이 μ 쪽으로 강하게 당겨져요. 그래서 '소재·표현 문제'와 '숨은 강자'는 아직 거의 나오지 않아요.

### 처방(반사실 예측)
해당하는 특성 하나를 바꿨을 때 μ가 얼마나 바뀌는지 계산해서, +2%p 이상인 것을 큰 순서로 최대 3개 내요.

| 바꾸는 것 | 방법 |
|---|---|
| 특정 경험 전제 | 없애요 |
| 경험 전제 | 없애요 |
| 시점 | 빼요 |
| 은유 | 걷어내요 |
| 예/아니오형 | 양자택일로 바꿔요 |
| 일화 회상 | 성향형으로 바꿔요 |
| 성향·개념·인물형 | 선택지를 주는 양자택일로 바꿔요 |
| 길이 | 30자 안팎으로 줄여요 |

- 관찰 데이터라서, 처방 효과는 '같은 특성을 가진 다른 질문들에서 본 차이'예요. 실제 효과는 13절(수정 효과 측정)로 확인해요.

### 우선순위
- **우선순위 = 기대 이득 × 상대 노출**
  - 기대 이득 = max(처방 후 μ, 평균) − θ
  - 상대 노출 = 그 질문 노출 ÷ 평균 노출
- 대상: 등급 C·D 중 아래에 해당하지 않는 질문이에요.
  - 수정안이 있는 질문
  - 골라 주세요에 있는 질문
  - 그대로 두기로 한 질문
  - 검토에서 고른 질문
- 개선함 '고쳐야 할 것' 탭이 이 순서로 보여 줘요.

### 구조 선택과 검증
- **관심사×형식 상호작용:** 매달 교차검증으로 넣을지 정해요. 로그우도가 1.0 이상 좋아질 때만 넣어요(절약 원칙). 2026-10에는 +0.9이라 넣지 않았어요.
- **소주제 더미:** 교차검증에서 오히려 나빠졌어요(λ=10에서 −4.5). 그래서 넣지 않아요.
- **특성 묶음별 λ 분리:** 이득이 없었어요.
- **시간 외 검증:** 2026-09-25 통계로 학습해서, 2026-10-01까지 새로 쌓인 결론 293회(문항 227개)를 예측했어요. 결론당 로그 손실은 이래요.

## 1. 무엇을 예측하나

- 결과 변수는 문항 i의 **답변 a_i / 결론 n_i**예요. 결론은 답변과 교체를 더한 수이고, 미응답은 결론이 나지 않은 노출이라 뺐어요.
- 문항당 결론이 아주 적어요. 중앙값이 2회예요. 그래서 관측 답변율 a/n을 그대로 믿으면 안 되고, 모델이 그 불확실성을 직접 다뤄야 해요.

## 2. 평가 모델: 릿지 규제 베타-이항 회귀

```
θ_i ~ Beta(μ_i·φ, (1−μ_i)·φ)          문항 i의 진짜 답변율
a_i | θ_i ~ Binomial(n_i, θ_i)
logit μ_i = β0 + Σ_j β_j · x_ij        x = 문항 특성
목적함수 = −Σ log BetaBinomial(a_i | n_i, μ_i, φ) + λ · Σ_j β_j²
```

- **베타-이항:** 같은 특성의 문항끼리도 진짜 답변율이 다른 것(과산포)을 φ 하나로 데이터에서 추정해요. 2026-10 기준 φ≈58이에요.
- **릿지(λ):** 특성끼리 겹쳐 있어서(예: 시점 고정 ↔ 경험 전제) 계수가 흔들리기 쉬워요. λ는 문항 단위 5겹 교차검증으로 {3, 10, 30} 중에서 골라요. 2026-10 기준 λ=10이에요.
- **특성 x:** 아래 SPEC의 26개예요. 기준값은 형식이 성향·습관, 관심사가 가치관이에요.
  - 시점 고정 / 특정 날 시점
  - 경험 전제 / 특정 경험 전제
  - 즉답 가능 / 깊은 성찰
  - 감정 무게 / 무거운 감정
  - 자기노출 / 높은 자기노출
  - 은유·모호
  - 40자 초과, 로그 글자 수
  - 레벨 1(첫 질문 자리)
  - 형식 7개
  - 관심사 5개
- **효과 구간:** 문항 부트스트랩 200회로 95% 백분위 구간을 내고, p값은 부호가 뒤집힌 비율의 두 배로 계산해요. 규제 때문에 효과가 0 쪽으로 조금 작게 나와요. 보수적인 쪽이에요.

### 문항별 추정(사후)
```
θ̂_i = (a_i + φ·μ_i) / (n_i + φ)
```
- 표본이 적은 문항은 '특성으로 예측한 값' μ_i 쪽으로 당겨져요.
- 이전 방식은 '전체 평균' 쪽으로 K=10만큼 당겼어요. 이제는 당기는 기준이 문항 특성에 맞춘 예측값이고, 당기는 강도 φ도 데이터가 정해요.

### 새 질문 예측
- μ = sigmoid(x·β)를 쓰고, 80% 예측 구간은 Beta(μφ, (1−μ)φ)로 내요. 페이지에서는 정규 근사를 써요.

## 6. 제작 모델

질문 생성기('새 질문 만들기')는 다음 순서로 후보를 만들고 골라요.
1. **빈 곳:** 관심사 × 자기 축(v2)의 신호형 수(목표 10), 얇은 소주제(8문항 미만), 첫 선택지 극 쏠림을 봐요. 칸은 (관심사, 축)이거나 (관심사, 성찰형/기록형)이에요.
2. **근거:** 그 칸과 관심사에서 잘 되는 질문, 안 되는 질문을 사후 추정 기준으로 뽑아요. 형식별 답변율과 확실한 효과도 함께 보여 줘요.
3. **소재:** AI가 넓은 일상 주제로 소재를 제안하면, 기존 질문과 단어가 겹치는지 판정해요.
4. **생성:** AI가 질문, 가이드, 태그(T·P·E·W·S·C·형식)를 만들어요. 가정형은 금지예요.
5. **점수:**
```
제작 점수 = 예상 답변율(μ)
          + 신호 부족 보너스 (신호형 질문: 그 축 신호형 5개 미만 +5%p, 10개 미만 +3%p)
            또는 얇은 소주제 보너스 (성찰·기록형: 소주제 8문항 미만 +3%p)
          + 극 균형 +1%p (첫 선택지를 적은 쪽 극으로 둔 신호형)
          − 중복 10%p (글자 2-gram Dice ≥ 0.6)
          − 소재 겹침 5%p(이미 많이 다룸) / 2%p(일부)
          − 가정형 3%p − 신호 방향 없는 신호형 2%p
```
6. **검토:** 사람이 제작 점수 순으로 보고 고르거나 고쳐서 추가해요. 추가한 질문은 노출된 뒤 다음 달 학습 데이터로 들어가요.

## 7. 다음에 하면 좋은 것

- **노출 맥락 기록:** 몇 번째 질문으로, 어떤 사용자에게 보였는지 기록되면 '레벨 1 효과'를 질문 효과와 자리 효과로 나눌 수 있어요.
- **신규 질문 노출 배분:** 탐색 중인 신규 질문에 노출을 조금 더 주면 판정이 빨라져요(톰슨 샘플링). 앱 쪽 협조가 필요해요.
- **태그 신뢰도:** 사람 태그와 AI 태그의 일치율을 재서, 생성기 예측에 태그 오차를 반영해요.

## 8. 레벨 구조 제안 (4단계)

지금은 레벨이 1(첫 질문)과 2(나머지) 두 개뿐이에요. 질문 깊이 태그로 4단계를 나누면 레벨이 오를수록 답변율이 내려가요(2026-10-01 실적).

| 레벨 | 정의 (`build_insights.level_of`) | 문항 | 실제 답변율 (95%) |
|---|---|---|---|
| 1 입문 | 원래 레벨 1이거나: 시점·경험 전제·은유 없음, 즉답, 가벼움, 자기노출 낮음, 선호·양자택일·상상형 | 398 | 56% (53~60) |
| 2 일상 | 나머지(성향·습관, 가벼운 생각) | 378 | 55% (51~59) |
| 3 성찰 | 깊은 성찰(E3), 감정·자기노출 둘 다 보통 이상, 일화 회상·개념형, 특정 경험 전제 | 324 | 40% (37~44) |
| 4 깊이 | 무거운 감정(W3) 또는 높은 자기노출(S3) | 51 | 40% (32~49) |

**기록 여정 (기록 횟수에 따라 섞는 비율)**

| 시기 | 레벨 비율 | 기대 답변율 |
|---|---|---|
| 1~3회째 | L1 100% | 56% |
| 4~14회째 | L1 40% · L2 60% | 56% |
| 15~30회째 | L1 20% · L2 50% · L3 30% | 51% |
| 31회째부터 | L2 45% · L3 40% · L4 15% | 47% |

**내보내는 규칙**
- 7일 넘게 쉬다 돌아오면 다음 2회는 입문(L1)으로 시작해요.
- 연속 2번 교체하면 다음 질문은 한 단계 낮춰요.
- L4는 주 1회 이하로, 연속으로 내보내지 않아요. 사용자가 끌 수 있게 해요.
- 같은 자아분석 축이 연속으로 나오지 않게 섞어요.

**적용과 검증**
- DB `question_level`을 1~4로 넓혀요. 지금 레벨 1은 그대로 1이에요.
- 지금 레벨 2인 126개가 입문 기준을 만족해요. 레벨 1 후보예요.
- L4는 51개뿐이고 취향·사랑은 1~4개라, 깊이 질문을 관심사별로 보강해야 해요.
- 비율은 가정이에요. 적용 후 시기별 답변율과 재방문율로 조정해요. 가능하면 A/B로 비교해요.

## 9. 출고 기준 (품질 게이트)

생성기와 '직접 써서 진단'에서 추가하기 전에 확인해요. 하나라도 걸리면 추가 버튼을 두 번 눌러야 하고, 걸린 항목은 `added` 문서의 `gate`에 남아요.

| 기준 | 값 | 근거 |
|---|---|---|
| 예상 답변율 | ≥ 평균 − 5%p | 평균보다 확실히 낮은 질문을 새로 늘리지 않아요 |
| 80% 예측 범위 하한 | ≥ 35% | 운이 나빠도 수정 대상(평균 −10%p)까지 떨어질 위험이 낮아요 |
| 중복 | 기존 질문과 글자 2-gram Dice < 0.6 | 중복 검토와 같은 기준이에요 |
| 가정형 | 없음 | 사용자 요청: if 질문을 피해요 |
| 특정 경험 전제 | 레벨 3 이상에서만 | 가장 큰 감점 요인이에요(−11%p) |
| 길이 | 35자 이하 | 길이 2배마다 −5%p, 20자 이하가 가장 높아요 |
| 신호 방향 | 신호형은 A/B 필수 | 축 판정에 필요해요 |
| 가이드 점검 | 아래 10절 | 기존 DB 말투를 지켜요 |

## 10. 가이드 점검 (lint)

- 가이드 세 개 모두 8~40자예요.
- '당신'을 쓰지 않아요.
- 힌트에는 떠올릴 예시나 선택지가 2~3개 있어요. 쉼표·'~나'·'~와'·'아니면'·'중' 같은 나열이 있는지로 봐요.
  - 지금 활성 질문 중 210개가 이 기준에 걸려요. 대부분 힌트가 질문 하나로만 돼 있어요.

카드 편집 칸에서도 실시간으로 보여 줘요. 기존 질문은 막지 않고 참고로만 보여 줘요.

- 같은 패밀리는 `added.fam`으로 묶여요.

## 12. 관심사 재배정 큐

**우선순위 규칙:** 다른 사람(친구·가족·동료·주변 사람, 남의 시선·인정·이해)이 중심인 질문은 가치관보다 관계가 우선이에요. 연애가 중심이면 사랑이 우선이에요.
- 그래서 관계·사랑 질문을 가치관으로 옮기는 제안은 내지 않아요.
- 가치관에 있던 사람 중심 질문은 관계(또는 사랑)로 옮기라고 제안해요.
  - 예: '이해받는 것과 인정받는 것', '혼자 일하는 것과 팀으로 일하는 것', '남의 시선을 얼마나 의식하나요'

후보는 두 가지 근거로 정해요. 결과는 `insights.json`의 `recat`에 들어가요.

| 근거 | 내용 |
|---|---|
| 사람 분류 | 수동 분류표의 '관심사 제안' |
| 문구 분류기 | 글자 2~3-gram TF-IDF + 로지스틱 회귀, 5겹 교차예측(정확도 약 61%) |

- 분류기만 내놓은 후보는 기준이 엄격해요.
  - 다른 관심사일 확률 ≥ 0.7이고 지금 관심사일 확률 ≤ 0.15여야 해요.
  - 가치관으로 옮기는 제안은, 지금 관계·사랑이거나 문구에 사람 단어가 있으면 내지 않아요(`PEOPLE_FIRST`, `PEOPLE`).
- 2026-10 기준 후보는 94개예요(사람·모델 둘 다 24 · 사람 분류만 48 · 모델만 22). 이 중 가치관 → 관계가 31개예요.
- 개선함 '검토할 것 → 관심사 재배정'에서 처리해요.
  - '옮기기'를 누르면 `edits.interest_id`가 바뀌고, CSV에 관심사 수정으로 나가요.
  - '그대로'를 누르면 `recatok`에 남아요.

## 13. 수정 효과 측정

- 앱 DB에서 문구를 바꾸면 통계의 Revision이 올라가요.
  - **수정 전:** 같은 질문의 '전체 Revision − 현재 Revision'
  - **수정 후:** '현재 Revision'
- 두 기간의 답변율을 비교해요(`build_insights.revision_effect`).
- **판정 기준:** 전·후 각각 결론 20회 이상인 질문만 합쳐 차이와 95% CI를 내요.
- **보정:** 같은 시기 전체 답변율 변화(계절·사용자 구성)를 빼려면, 수정하지 않은 질문들의 같은 달 변화와 비교해요(이중차분). 월별 스냅숏이 2개 이상 쌓이면 대조군 변화를 계산할 수 있어요.
- **현재 상태:** 2026-10 기준 Revision이 바뀐 질문이 0개라 대기 중이에요.

## 14. 앱 쪽 실험·명세 (협조 필요)

- **A/B 테스트(수정 효과를 가장 확실하게 재는 방법):**
  - 수정할 질문의 원문과 수정본을 사용자 무작위 50:50으로 4주 내보내요.
  - 주 지표는 답변율(답변 ÷ 결론)이에요.
  - **표본:** 기준 50%에서 10%p 차이를 검출력 80%로 보려면 팔당 결론 약 390회가 필요해요. 질문 하나로는 어려워요. 그래서 수정한 질문 20~30개를 묶어 '수정본 묶음 vs 원문 묶음'으로 비교해요(문항 무작위 효과 모델).
- **레벨 여정(8절) 앱 명세:**
  - DB `question_level`을 1~4로 넓혀요.
  - 사용자별 기록 횟수 구간으로 레벨 비율을 정하고, 그 안에서 관심사·축이 연속되지 않게 뽑아요.
  - 7일 넘게 쉬었다 돌아오면 L1 두 번, 연속 2회 교체하면 한 단계 낮춰요.
  - L4는 주 1회 이하예요.
- **노출 로그:** 질문 노출 순번(오늘 몇 번째), 레벨, 사용자 기록 횟수를 남기면 레벨 1의 자리 효과를 질문 효과와 나눌 수 있어요.
- **선택지 순서 무작위화:** 양자택일 선택지 순서를 사용자마다 섞으면 순서 효과를 없애고 크기도 잴 수 있어요.

## 16. 실험·측정 체계 (개선함 '분석 → 실험·측정')

**지표 층**

| 층 | 지표 | 2026-10-01 | 비고 |
|---|---|---|---|
| 최상위 | 7일 재기록률 · 주간 기록 사용자 비율 | — | 사용자 로그가 필요해요 |
| 주요 | 노출 대비 답변율(무응답 포함) | 44.8% | 목표·리포트용이에요 |
| 질문 평가 | 답변 ÷ (답변+교체) | 49.9% | 질문 비교용이에요 — 이유는 아래 |
| 보조 | 교체율 · 답변 시간 · 답변 길이 | 교체 45.0% | 시간·길이는 로그가 필요해요 |
| 가드레일 | 신호 목표를 채운 축 수 · 레벨 3~4 비중 | 14/19 · 32% | |

- 질문 평가에 무응답을 빼는 이유: 결론에 이르는 비율(1 − 무응답 비율)이 질문마다 다른 정도가 우연 수준이에요(표준편차 0.093, 우연이면 0.091). 그래서 무응답을 넣어도 질문 순위는 거의 같고 잡음만 늘어요.

**검정력 (화면 계산기)**

| 효과 크기 | 묶음당 필요한 결론 |
|---|---|
| +10%p | 388회 |
| +8%p | 608회 |
| +5%p | 1,565회 |

- 기준: 답변율 50%, 유의수준 0.05, 검정력 0.8
- 트래픽(09-25~10-01): 전체 결론 하루 55회, 수정한 질문 340개에는 하루 15.8회(29%)
- 반씩 나누면 +10%p 검출에 약 50일이 걸려요. 4주 안에 확실히 판정할 수 있는 효과는 ±13%p 정도예요.
- '3~4주로 +8~10%p'는 이 트래픽으로는 불가능해요.
- 기간을 줄이는 방법:
  - 실험 질문의 노출 비중을 올려요.
  - 같은 질문의 원문과 수정본을 사용자별로 무작위로 보여 줘요(앱 협조 필요, 가장 효율적).
  - 효과가 큰 처방 유형부터 실험해요.
- 분석 단위는 처방 유형별 묶음이에요.

**예측력 천장**
- 문항 간 진짜 답변율의 표준편차는 0.065예요(φ=58).
- 진짜 답변율을 정확히 아는 예측자도 결론당 로그 손실을 0.0085만 줄일 수 있어요.
- 지금 모델의 시간 외 개선은 0.0025로, 천장의 약 29%예요. 검증 기간이 6일이라 흔들려요.
- '평균 대비 0.4%'는 이 천장과 견줘서 읽어야 해요.

**태깅 신뢰도**
기준 태그(평가자 1명, 875문항)와 문구 규칙 자동 태그를 비교한 κ예요.

| 특성 | κ |
|---|---|
| 시점 | 0.88 |
| 경험 전제 | 0.44 |
| 형식 | 0.44 |
| 은유 | 0.20 |
| 감정 무게 | 0.11 |
| 인지 노력 | 0.10 |
| 자기노출 | 0.01 |

- 자동 태그로 하는 예측(진단기·카드 편집·고친 문구)은 인지 노력, 감정 무게, 자기노출을 믿기 어려워요.
- 다음 단계: 사람 2명과 AI가 질문 100개를 따로 태깅해 κ를 재요. 사람끼리도 0.6 미만인 특성은 정의를 다시 쓰거나 모델에서 빼요.

**탐색 노출(톰슨 샘플링)**
- 설계 예측 μ를 사전분포 Beta(φμ, φ(1−μ))로 써요.
- 탐색 비중 10%로 30일이면 결론 165회예요. 결론 5회 기준으로 판정되는 새 질문은 33개, 20회 기준으로 확정되는 건 8개예요.

**실험 노트**

  - 고치기 전 문구
  - 전·후 설계 예측과 기대 효과
  - 처방 유형: 경험 전제 제거 · 시점 제거 · 은유 제거 · 양자택일 전환 · 단축 · 표현·소재 변경
